# Security Policy

## Reporting Security Vulnerabilities

We take security vulnerabilities seriously. If you discover a potential vulnerability in `fcode`, please report it through GitHub's Private Vulnerability Reporting rather than public issue trackers.

### Preferred Reporting Method

Please submit your report privately using GitHub Security Advisories:
1. Navigate to the repository's **Security** tab.
2. Select **Advisories** from the sidebar.
3. Click **Report a vulnerability** to open a private advisory draft.

This ensures that the discussion, reproduction steps, and eventual patch remain confidential until a coordinated security advisory is published.

### What to Include in Your Report

To help us investigate and triage effectively, please include:
* Description of the vulnerability and its potential impact.
* Step-by-step reproduction instructions or proof-of-concept code.
* Specific files, functions, or execution flows involved.
* Any potential remediations or workarounds you have identified.

### Response Commitments

* **Initial Acknowledgment:** Within 48 hours of report submission.
* **Triage and Status Update:** Within 5 business days with assessment results.
* **Fix and Disclosure:** Coordinated release and public disclosure following fix validation.

We ask that you refrain from disclosing the vulnerability publicly until an official fix has been released.
