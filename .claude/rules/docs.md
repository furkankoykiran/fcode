# Scoped Rule: Documentation & Presentation Integrity

1. **Independent Product Identity:** Public documentation must describe fcode's own concepts, architecture, and principles directly. Never expose internal research sources, competitor comparisons, lineage claims, external repository links, or visual inspirations in public files.
2. **Reality vs. Vision:** Clearly separate the current pre-implementation foundation from future roadmap phases. Never advertise unbuilt features, fictitious install commands, or synthetic benchmarks.
3. **Link & Asset Verification:** All relative paths referencing assets or documents must be verified to physically exist before saving edits.
4. **Writing Discipline:** Follow direct human writing standards. Do not use em dashes. Avoid inflated promotional language, corporate fluff, and artificial filler phrases.
