# Scoped Rule: Documentation & Presentation Integrity

1. **Product Identity:** Public documentation describes fcode's architecture, principles, and capabilities directly and objectively.
2. **Reality vs. Vision:** Clearly distinguish the current foundation from future roadmap phases. Never advertise unbuilt features, fictitious install commands, or unverified benchmarks.
3. **Link & Asset Verification:** All relative paths referencing assets or documents must be verified to physically exist before saving edits.
4. **Clarity and Precision:** Use clear, direct technical prose. Avoid inflated promotional language and vague filler phrases.
